# Kintore — App Store 提出 完全手順書

本書は **Kintore（Bundle ID: `com.kintore.app`）** を App Store に公開するための作業手順と、**App Store Connect にそのまま転記できる入力例**をまとめたものです。  
審査基準・画面仕様は変更されるため、提出直前に [App Store レビューガイドライン](https://developer.apple.com/jp/app-store/review/guidelines/) と [App Store Connect ヘルプ](https://developer.apple.com/help/app-store-connect/) を確認してください。

---

## 1. 本アプリの固有情報（確認用）

| 項目 | 内容 |
|------|------|
| アプリ名（表示名） | **Kintore**（`INFOPLIST_KEY_CFBundleDisplayName`） |
| Bundle ID | **com.kintore.app** |
| 対応 OS | **iOS 17.0 以降**（`project.yml` の deploymentTarget） |
| 対応デバイス | **iPhone**（`TARGETED_DEVICE_FAMILY: 1`） |
| 埋め込みターゲット | **Kintore Watch**（ウォッチアプリ）、**Kintore Widget**（ウィジェット拡張）— 同一ストアの 1 バイナリに含まれる |

| ヘルス | **HealthKit** — ワークアウトの**書き込み**（ユーザーが設定で ON のとき）。用途説明は `NSHealthUpdateUsageDescription`（日英 `InfoPlist.strings`） |

## 2. 事前準備（必須）

1. **Apple Developer Program** に登録済みであること（年額）。  
2. **Apple ID** が **開発チーム**に紐づいていること。  
3. **Mac + Xcode**（プロジェクトは Xcode 16 系想定）でアーカイブ可能であること。  
4. **プライバシーポリシー**を **公開 URL** で閲覧できるようにすること（後述のテンプレに沿って作成し、GitHub Pages / 自サイト / Notion 公開などでホスト）。  
5. **連絡用メールアドレス**（審査・サポート用）。  
6. **スクリーンショット**（Apple が求める **必須デバイスサイズ**分。既に撮影済みなら、そのセットを各スロットに割り当て）。

---

## 3. Apple Developer — Identifiers / Capability 確認

1. [Certificates, Identifiers & Profiles](https://developer.apple.com/account/resources/identifiers/list) を開く。  
2. **Identifiers** → **App IDs** で **`com.kintore.app`** を確認。  
3. 有効化されている **Capability** が Xcode の **Signing & Capabilities** と一致していること：  
   - HealthKit  
   - iCloud（CloudKit を含む設定）  
   - App Groups（`group.com.kintore.app` 等、プロジェクトと一致）  
4. **App Store Connect** 用に **App** が未登録なら、後述の手順で作成する。

---

## 4. Xcode でのリリースビルド設定

1. プロジェクトを開き、**Target「Kintore」** を選択。  
2. **Signing & Capabilities**  
   - **Team** を選択。  
   - **Bundle Identifier** が `com.kintore.app`。  
   - **Automatically manage signing** を通常は ON。  
3. **General**  
   - **Version**（マーケティング版）例: `1.0.0`  
   - **Build**（ビルド番号）: 提出のたびに **必ず増やす**（例: `1`, `2`, …）。  
4. **アーカイブ用スキーム**  
   - メニュー **Product → Scheme → Kintore**  
   - **Any iOS Device (arm64)** または実機接続状態で、シミュレータはアーカイブ不可。  
5. **Product → Archive**  
6. **Organizer** が開いたら、**Distribute App** → **App Store Connect** → 手順に従い **Upload**。  
7. アップロード完了後、**App Store Connect** の **ビルド**に反映されるまで **数分〜数十分**かかることがある。

**注意:** Watch / Widget は同じアーカイブに含まれるため、**別途 Watch だけ提出**は不要（通常は同一アプリのバイナリ）。

---

## 5. App Store Connect — 新規アプリの作成

1. [App Store Connect](https://appstoreconnect.apple.com) にログイン。  
2. **マイ App** → **「+」** → **新規 App**。  
3. 入力例：  

| フィールド | 入力例 |
|------------|--------|
| プラットフォーム | **iOS** |
| 名前 | **Kintore**（表示名が他アプリと被る場合は変更が必要なことがある） |
| 主要言語 | **日本語** |
| Bundle ID | **com.kintore.app**（ドロップダウンから選択） |
| SKU | 内部用の一意な識別子（例: **`kintore-ios-1`**） |
| ユーザーアクセス | 必要に応じて（個人開発ならフルアクセスで可） |

4. 作成後、左メニューから **アプリ情報**・**価格および配信状況**・**App のプライバシー** などを順に埋める。

---

## 6. アプリ内課金（非消耗型プレミアム）の登録

商品 ID はコードと **完全一致**させる: **`com.kintore.app.premium`**

1. App Store Connect → 該当アプリ → **機能** → **App 内課金** → **+**  
2. 種類: **非消耗型**  
3. **参照名**（管理用）例: `Kintore Premium`  
4. **商品 ID**: **`com.kintore.app.premium`**  
5. **価格**を選択。  
6. **ローカリゼーション**（表示名・説明）を少なくとも **日本語** で入力。  

**表示名・説明の例（要調整）**

- **表示名**: `Kintore プレミアム`  
- **説明**:  
  `高度な分析・比較機能、共有カード、クラウド同期の利用など、プレミアム機能をアンロックします。買い切り型の購入です。`

7. **審査用スクリーンショット**（課金画面が表示される箇所）が求められることがある。設定画面のプレミアム案内などをキャプチャして用意する。  
8. **提出**状態にし、**アプリのバージョン**と同じ審査バッチに含める。

## 8. App のプライバシー（必須）

**虚偽の申告はリジェクトやアカウントリスクにつながります。** 以下は **実装の目安**であり、**Google Mobile Ads SDK の最新のデータ取り扱い**に合わせ、必要なら [Google の開示ガイド](https://developers.google.com/admob/ios/privacy) を確認のうえ選択してください。

### 8.1 本プロジェクトから読み取れる範囲

- **トレーニング記録・体重・回数など**: アプリのコア機能。ローカル（SwiftData）および、プレミアム・iCloud 設定に応じて **ユーザーの iCloud / CloudKit** に保存される設計。  
- **HealthKit**: ユーザーが設定で有効化した場合、**完了ワークアウトの保存**に使用。  
- **購入**: StoreKit の取引情報。  
- **通知**: リマインダー等（`UserNotifications`）。ユーザーが許可した場合。  
- **広告**: AdMob。**広告のパーソナライズ・トラッキング**に関する Apple の要件（ATT 等）を、SDK・実装に応じて満たすこと。本リポジトリには **AppTrackingTransparency の呼び出しは含まれていない**（コード検索時点）ため、**広告のみで IDFA を使うか**は依存ライブラリ・設定次第。**不確実な場合はリーガル・ドキュメントと照合すること。**  
- **分析イベント**: 実装は主に **端末ログ**。外部アナリティクスに送信するコードが無い場合、**「収集しない」**の根拠になる。

### 8.2 入力時の心構え

- データを **連結しない**、**端末上のみ** など、各データ種別について Apple の質問に **正直に** 回答する。  
- **プライバシーポリシー URL** の内容と **矛盾させない**。

| 項目 | 入力例 |
|------|--------|
| **ログインが必要か** | アカウント不要で利用可能な場合: **ログイン不要** と明記。 |

**審査メモ例（コピー用）**

```text
【ログイン】アカウント登録は不要です。
```

## 14. 年齢レーティング

2. 本アプリのような **トレーニング記録** が主で、不適切コンテンツが無い通常ケースでは **低年齢帯** になりやすいが、**質問内容は必ず最新のフォームに従うこと**。

## 15. プライバシーポリシーに含めるべき項目（ひな型）

公開 URL 用に、最低限以下を文章化する（**法的助言ではありません**。必要に応じて専門家に相談）。

1. 事業者名・連絡先  
2. 収集するデータの種類（トレーニング内容、端末情報、購入情報、HealthKit の取り扱い、広告 SDK に関するデータ 等）  
3. 利用目的  
4. 第三者提供（広告パートナー、Apple、Google 等）の有無と概要  
5. 保存期間・削除・ユーザーからの請求方法  
6. iCloud / HealthKit の利用条件  
7. 未成年者（該当する場合）  
8. 改定日

## 16. 提出とリリース

1. 上記をすべて入力し、**審査に提出**をクリック。  
2. **審査中**は **メール**を監視（追加情報の依頼がある場合がある）。  
3. **承認**後、**リリース**を **手動**か **自動**か選択。  
4. **「利用可能」**になったら App Store で検索可能になる（反映に時間がかかることがある）。
