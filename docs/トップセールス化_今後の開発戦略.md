# RepLog トップセールス化 — 今後の開発戦略

**前提**: Phase 5〜10（バグ修正・グラフ・iCloud・Watch・課金・オンボーディング）は完了済み。  
**目的**: 日本の筋トレメモアプリカテゴリでトップセールスを目指すための、リリース後〜中長期の開発・運用戦略。

---

## 1. 戦略の柱（3本柱）

| 柱 | 狙い | 具体アクション |
|----|------|----------------|
| **認知・獲得（ASO・訴求）** | 検索・ストアで「筋トレ 記録」層に届き、差別化が伝わる | キーワード・スクショ・キャッチコピー・紹介文の最適化 |
| **定着・継続（リテンション）** | 初回記録→2回目→習慣化の導線を強くする | 通知設計・再開導線・ストリーク/サマリの見せ方 |
| **収益・信頼（コンバージョン・口コミ）** | 無料で価値を実感→プレミアム転換・レビュー獲得 | プレミアム体験設計・レビュー誘導・データ安心訴求 |

---

## 2. 差別化の「守り」と「攻め」

### 守るべきポジション（競合に奪われないようにする）

- **広告なし** … 無料でも広告を一切入れない。ストア説明・スクショで明記し続ける。
- **記録の最速** … 起動→記録のステップ数・タップ数は常に計測し、リグレッションを防ぐ。
- **前回値・PRの視認性** … 記録画面の情報配置は変えず、読みやすさを維持。
- **iCloud・データ保護** … 消失リスクの話題が出るたびに「RepLogはiCloudで守れる」を訴求。

### 攻める場所（競合の不満を埋める）

- **グラフ** … 筋トレMemoの「グラフが分かりにくい」不満を逆に差別化に。種目別・週次ボリューム・PRマーカーを「見やすい」と感じてもらう説明をストア・SNSで繰り返す。
- **日本語ファースト** … Hevy/Strong から流れてくる層に「日本語で迷わない」を打ち出す。
- **買い切りで同じ価格帯** … 筋トレMemoと同程度の価格で「広告なし・バックアップあり」を対比できるようにする。

## 3. フェーズ別ロードマップ（リリース後〜12ヶ月）

### Phase 11: リリース・ASO・計測基盤（リリース〜1ヶ月）

**目的**: ストアで差別化が伝わり、数字を見れる状態にする。

| タスク | 内容 | 優先度 |
|--------|------|--------|
| ストア公開 | スクリーンショット4枚以上（記録画面・グラフ・ホーム・Watch）、キャッチコピー・説明文の確定 | 必須 |
| サブタイトル・キーワード | 「筋トレ 記録 広告なし」「iCloud バックアップ」「グラフ」等をASO用に整理 | 必須 |
| 分析基盤 | App Store Connect の指標（インプレッション・コンバージョン・クラッシュ）の定期確認。必要なら Firebase / TelemetryDeck 等で起動・記録完了・購入イベントを軽量計測 | 高 |
| レビュー対応 | 悪意のない低評価には丁寧に返信し、改善可能な要望はバックログに記載 | 高 |

**成果指標**: ストアコンバージョン率（ページ閲覧→インストール）、初回起動数、クラッシュ率。

---

### Phase 12: リテンション強化（1〜3ヶ月）

**目的**: 1回記録で終わりにせず、2回目・週1回の習慣につなげる。

| タスク | 内容 | 優先度 |
|--------|------|--------|
| 通知設計の見直し | 休憩終了のみでなく「○日ぶりです。記録を再開しませんか？」等の再開リマインド（頻度は控えめに） | 高 |
| ホームの「続きから」強化 | 未完了セッションがあれば目立つバナーで再開を促す（既存の記録導線と矛盾しない範囲で） | 中 |
| 週次サマリの通知 | オプションで「今週○回実施しました」を週末に1回送る。許可は設定でオフ可能に | 中 |
| ストリーク・継続の可視化 | 統計の「連続実施週」をホームやウィジェットで軽く見せる（過度なゲーミフィケーションは避ける） | 中 |

**成果指標**: D1/D7/D30 リテンション、週あたり記録セッション数、通知許可率。

---

### Phase 13: コンバージョン・信頼の最適化（2〜4ヶ月）

**目的**: 無料で価値を実感したユーザーがプレミアムに転換し、レビューで背中を押す。

| タスク | 内容 | 優先度 |
|--------|------|--------|
| プレミアム体験の「見せ方」 | グラフ1ヶ月制限に達したタイミングで「3ヶ月・全期間を見る」の CTA、iCloud/エクスポートの安心を1画面で説明 | 高 |
| レビュー誘導の強化 | 10回目セッション完了に加え、プレミアム購入直後の「使ってみてどうですか？」でレビュー依頼（スパムにならない頻度で） | 高 |
| データ安心の訴求 | 設定の「記録○セッション・○セット」に加え、「iCloudでバックアップ済み」（プレミアム時）等の短いメッセージ | 中 |
| 価格・訴求の A/B テスト | サブタイトルやスクショの「広告なし」「買い切り」の打ち出しを変えてコンバージョンを見る（可能なら StoreKit の offer も検討） | 低 |

**成果指標**: 無料→プレミアム転換率、レビュー数・平均評価、課金単価。

---

### Phase 14: 機能拡張で差別化を深掘り（4〜8ヶ月）

**目的**: 競合が真似しにくい「記録が速い・データが守られる・グラフが分かりやすい」をさらに強める。

| タスク | 内容 | 優先度 |
|--------|------|--------|
| ウィジェット | ホーム画面に「今週○回」「直近PR」を表示。再開のきっかけにする | 高 |
| Watch の拡張 | 休憩＋Haptic に加え、セット完了の簡易入力（重量・回数を選んで送信）で iPhone と連携 | 中 |
| グラフの追加 | 部位別の週次トレンド、月間ボリューム比較など、統計画面の訴求を1つ増やす | 中 |
| エクスポート強化 | CSV に加え、日付範囲指定やバックアップ日時表示で「データを手元に」を明確に | 低 |
| アクセシビリティ | VoiceOver・Dynamic Type の確認とラベル整備。ストアで「使いやすい」を打ち出せるようにする | 中 |

**成果指標**: ウィジェット利用率、Watch セッション数、統計画面の閲覧率。

---

### Phase 15: スケール・持続可能性（6〜12ヶ月）

**目的**: ユーザー数・レビュー・収益が伸びても、品質と開発持続性を保つ。

| タスク | 内容 | 優先度 |
|--------|------|--------|
| パフォーマンス・大容量対応 | 履歴数千件・種目数百件でも軽い起動・スクロールを維持。SwiftData/CloudKit のクエリ最適化 | 高 |
| 多デバイス・同期 UX | 同じ Apple ID で iPhone / iPad を使う場合のコンフリクト表示や「最新はこちら」の案内 | 中 |
| ローカライズ | 英語のストア説明・アプリ内テキストを用意し、海外からのインストールにも対応（日本語を主軸にしたまま） | 低 |
| サブスク検討 | 買い切りを主軸にしつつ、年額サブスク＋永久購入オプションを計画書どおり検討。価格は市場と自社コストのバランスで | 低 |

**成果指標**: クラッシュ率・起動時間、同期エラー率、地域別インストール・収益。

## 4. 成功指標（KPI）の整理

| 指標 | 目安（例） | 計測方法 |
|------|------------|----------|
| ストアコンバージョン率 | インストール/ページ閲覧 25% 以上 | App Store Connect |
| D7 リテンション | 25% 以上 | 分析基盤 or Connect |
| 週1回以上記録率 | アクティブユーザーの 40% 以上 | 自前 or 分析基盤 |
| 無料→プレミアム転換率 | 2〜5% 程度（買い切り前提） | StoreKit / Connect |
| 平均評価 | 4.0 以上維持 | App Store Connect |
| クラッシュ率 | 1% 未満 | Connect / Xcode Organizer |

※ 数値は筋トレメモ系の一般的な水準を参考にした例。実績を見て目標を更新する。

---

## 5. リスクと対策

| リスク | 対策 |
|--------|------|
| 競合が広告をやめたりグラフを改善する | 差別化は「広告なし・iCloud・最速」の組み合わせで打ち出す。単一機能に依存しない。 |
| ストアで埋もれる | ASO を継続し、SNS・ブログ・フィットネス系メディアでの紹介を少しずつ試す。 |
| 課金率が伸びない | 無料で「グラフ1ヶ月」「iCloudなし」を体験したあとの CTA と説明を改善。価格は ¥500 前後の買い切りを維持し、安心感を訴求。 |
| データ消失のクレーム | iCloud 有効時は「バックアップ済み」を設定で表示。エクスポートの手順をヘルプや設定内で案内。 |

---

## 6. 開発の進め方（運用方針）

- **スプリント**: 2週間単位で「ASO」「リテンション」「コンバージョン」「機能」のいずれかに重点を置く。
- **バックログ**: ユーザー声・レビュー・ストアの競合変化を元に、Phase 11〜15 のタスクを常に更新する。
- **品質**: 新機能は「記録の最速」「クラッシュなし」を壊さないことを条件にリリースする。
- **ドキュメント**: 差別化ポジション・KPI・今フェーズの重点はこの戦略書と計画書を参照し、判断の軸を揃える。

---

## 7. まとめ

- **短期（〜1ヶ月）**: ストア公開・ASO・計測で「見える化」する。  
- **中期（1〜4ヶ月）**: リテンションとコンバージョンで「使ってもらう・買ってもらう・レビューしてもらう」を強化。  
- **長期（4〜12ヶ月）**: ウィジェット・Watch・グラフで差別化を深掘りし、パフォーマンスと持続可能性を確保する。  

**ポジションは変えない**: 「広告なし・グラフが綺麗・iCloudでデータ守れる・記録が最速の日本語筋トレアプリ」を守りつつ、上記フェーズで獲得・定着・収益を回していく。
