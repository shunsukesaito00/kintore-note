# Kintore 現状仕様書（AI分析用）

最終更新: 2026-03-28  
対象: iOSアプリ `Kintore`（SwiftUI + SwiftData）

## 1. プロダクト概要

- 目的: 筋トレの記録、履歴参照、統計確認を行うアプリ
- 主な価値:
  - ワークアウト中の素早いセット入力
  - 前回記録の参照・コピー
  - PR（自己ベスト）と推定1RMの可視化
  - 履歴・カレンダー・ホーム集計で継続しやすくする
- **課金**: StoreKit 2 の**買い切りプレミアム**（`PremiumService`）。統計の長期グラフ・共有カード・CSV 等の一部機能をプレミアムで解放。無料でも基本記録・履歴・当日保存は利用可能。

## 2. 技術・アーキテクチャ

- UI: SwiftUI
- 永続化: SwiftData
- **Apple Watch**: `WatchConnectivity` で休憩・PR を Watch に送信。Watch から「セット完了」または **重量（kg）・回数を指定して完了**（`setWeightRepsComplete`）を受け、記録画面が開いているときのみ `WorkoutRecordViewModel.applyWatchWeightRepsComplete` で先頭の未完了セットに反映（重量×回の種目のみ）。
- **HealthKit（任意）**: 設定で ON のとき、ワークアウト保存完了後に `traditionalStrengthTraining` として `HKWorkout` を書き込み（[`HealthKitWorkoutService`](Kintore/Core/Services/HealthKitWorkoutService.swift)）
- 主要層:
  - `Core/Models`: 永続モデル
  - `Core/Repositories`: CRUD/検索
  - `Core/Services`: 集計、PR、前回記録、通知など
  - `Modules/*`: 画面単位のView/ViewModel
- **ウィジェット**: `WidgetDataStore` が App Group に今週の実施回数・**連続実施週数**（`WorkoutStatsService.currentStreakWeeks` と同じ定義）・直近PR を書き込み。更新後に `WidgetCenter.shared.reloadTimelines(ofKind: "RepLogWidget")`。
- **ウィジェットタップ → アプリ**: メインアプリにカスタム URL スキーム `kintore` を登録（`Kintore/Info.plist` の `CFBundleURLTypes`）。ウィジェットは `.widgetURL(URL(string: "kintore://home")!)` で起動。`KintoreApp` の `.onOpenURL` で `AppDeepLinkHandler.apply` が呼ばれ、`UserDefaults` の `kintore.mainTabIndex` を更新して `MainTabView` の `TabView(selection:)` がホーム等に切り替わる。ホスト例: `kintore://home`（省略可）, `kintore://history`, `kintore://statistics`, `kintore://settings`。
- **ローカライズ（Phase 15・着手）**: [`Kintore/Resources/Localizable.xcstrings`](Kintore/Resources/Localizable.xcstrings) に英語（`en`）・日本語（`ja`）を定義。タブ・ナビタイトルに加え、**オンボーディング全文**、ホーム／履歴の読み込み、**履歴一覧のセクション見出し・空状態・日別シート**、**ルーティン一覧（件数表記含む）**、**種目一覧（検索・スワイプ・追加シートのナビ／ツールバー）**、ワークアウト開始・**記録画面のツールバー・経過時間・保存／破棄アラート**、セッション詳細のナビタイトルを `String(localized:)` / `String(format:)` で切替。設定・統計の長文などは未移行（順次カタログへ移行可能）。
- **多デバイス同期の案内（Phase 15）**: 設定の「データ」フッター（プレミアム時）に、同じ Apple ID の iPhone / iPad で iCloud 同期される旨・反映遅延・**複数端末編集時は最後の保存が優先**（競合解決 UI は未実装）を短文で表示。
- **分析イベント（Phase 11）**: `AnalyticsEventService`。DEBUG は `print`、**Release 含め全構成で `os.Logger`（subsystem: Bundle ID, category: Analytics）** に `event=…` 形式で記録（TestFlight / デバイス接続時の Console で確認可能）。**現行の列挙**（`AnalyticsEvent` と対応）: `app_launch` / `session_completed` / `premium_purchased` / `onboarding_completed` / `notification_permission_granted` / `deep_link_opened` / `statistics_screen_viewed` / `premium_promo_opened` / `csv_exported` / `share_card_shared` / `retention_insight_shown`。Firebase Analytics 追加時は同じ event 名で `Analytics.logEvent` を `log` 内に追記可能。
- **ローカル通知（Phase 12）**: `RetentionNotificationService`。再開リマインドはセッション保存後に3日後1本（`最後の記録から3日が経ちました。再開しませんか？`）。週次サマリは **次の土曜20:00** の非繰り返し1本。本文は `WorkoutStatsService` の今週の完了セッション数に基づき `今週 N 回のワークアウトを記録しました` または 0 回時の案内。アプリ起動時・`WidgetDataStore.updateFrom`・設定トグルで `syncWeeklySummarySchedule(modelContext:)` を再実行。
- **クエリ最適化（Phase 15）**: 完了セッション件数・セット数は `WorkoutRepository.countCompletedSessions` / `countSetsInCompletedSessions`（`fetchCount`）。レビュー依頼の 10 回判定も同様。統計の「全期間総挙上」は `WorkoutStatsService.totalVolumeAllCompletedSessions` で 200 件ずつページング。週次グラフ・週次セッション数は直近グラフに必要な期間だけフェッチ。部位別集計・連続週は全期間の値を維持しつつ、完了セッションを 200 件ずつページングして集約（メモリ上に全セッションを同時展開しない）。
- フォーマット/テーマ:
  - `AppFormatters`: 重量・日付フォーマット
  - `AppTheme`: 色・余白・タイポトークン。**Dynamic Type（Phase 14）**: 固定 `Font.system(size:)` をやめ、`title2` / `title3` / `body` / `caption` / `caption2` / `footnote` および `Font.system(.style, design: .rounded)` で記録・表系の数字を定義し、本文サイズ変更に追従

## 3. データモデル（主要）

- `WorkoutSession`
  - セッション単位（開始・終了時刻、種目群）
- `WorkoutExercise`
  - セッション内の1種目（順序、タグ、メモ）
  - `supersetGroupId: UUID?` … 隣接2種目をスーパーセットにしたとき同じID（単独は nil）
- `WorkoutSet`
  - 重量・回数・完了時刻・種別・RPE・補助フラグ
  - `isAssisted: Bool?`
    - `true`: 補助あり
    - `nil/false`: 補助なし扱い
    - 注: 既存ストア互換のため Optional 運用
- `Exercise`
  - 種目マスタ（部位、器具、デフォルト休憩秒など）
- `PersonalRecord`
  - 種目ごとのPR（定義は後述）
- `BodyMeasurement`
  - 身体記録（`measuredAt`、任意の `weightKg` / `bodyFatPercent` / `note`）。永続化は SwiftData。設定の「身体記録」から一覧・追加・スワイプ削除。

## 4. PR/RMの定義

- PR（自己ベスト）定義:
  - **1セットの挙上量（重量×回数）が最大**の記録
  - `PersonalRecordService` で更新判定
- 推定1RM:
  - Epley式 `weight * (1 + reps / 30)` を使用
  - 種目詳細から「推定1RM根拠」画面で確認可能

## 5. 主要画面仕様

### 5.1 ワークアウト開始画面（`WorkoutStartView`）

- ルーティン、部位別種目から記録開始
- 種目ごとに「前回からN日」表示
- **廃止済み**: 適応型「今日の提案」ブロック、および設定にあった**トレーニング環境**（ジム種別）ピッカー。関連ロジック（`AdaptiveProgramService` 等）は削除。
- 記録画面（fullScreenCover）から戻る時:
  - 保存成功時は `SessionDetailView` へ遷移（保存内容を即確認可能）
  - 保存せず取り消し時は開始画面に戻る

### 5.2 ワークアウト記録画面（`WorkoutRecordView`）

- ナビゲーション:
  - 左上: 「取り消し」
    - 入力がある時のみ確認ダイアログ
    - 保存せず破棄して戻る
  - 右上: 「保存」
    - 保存確認後、セッション保存
- 種目カード:
  - 種目名ヘッダーは青系帯
  - 「前回セッションのセットをすべて反映」ボタン
  - 前回記録パネルと今回入力の間に区切り線
- セット行入力:
  - 重量（小数対応）・回数・完了
  - 前回同順セットコピー
  - 直上セットコピー
  - 種別、RPE、補助あり/なし
- 種目ヘッダーの「…」メニュー:
  - **次の種目とスーパーセット**（直下の種目とペア）
  - **スーパーセットを解除**
  - **全セットをウォームアップに**（重量×回の種目のみ）
  - 種目の並べ替えでスーパーセットは自動解除
- メモ:
  - ラベル表示あり
  - 複数行入力（縦方向）
  - 視認性向上の枠線付き入力欄
- 休憩:
  - セット完了で自動休憩開始（種目設定 or ユーザー既定）
  - バックグラウンド対応のローカル通知（終了時）
- **Apple Watch**（プレミアム・記録画面表示中）:
  - Watch から「送信して完了」で重量（kg）・回数を送り、**先頭の未完了セット**（重量×回の種目）に反映して完了
  - 「入力せず完了」は従来どおり値を変えずに完了のみ
- **廃止済み**: 次セットの重量・回数・休憩の**自動提案** UI（メモセッション上の提案バー）。前回コピー・行単位コピー等は従来どおり。

### 5.3 セッション詳細（`SessionDetailView`）

- セッション内の種目・セットを表示
- 重量は小数を保持して表示
- 補助セットは「補助」ラベル表示
- 共有テキスト生成あり
- **もう一度記録**（ツールバー）: 完了済みセッションから `WorkoutSessionDraft(repeating:)` を生成し `WorkoutRecordView` を全画面表示。保存後は **新しいセッション詳細** に切り替え（`WorkoutSessionDraft+Repeat`）。削除済み種目はスキップ。スーパーセットIDは再実行時クリア。

### 5.4 設定・身体記録（`BodyMetricsView`）

- 設定の「記録」セクションから遷移
- 体重・体脂肪率のいずれか（または両方）を入力して保存（体重は内部で kg 保存、表示は設定の kg/lb に追従）
- 記録がある項目（体重・体脂肪率）ごとに **Swift Charts** で推移グラフ（線＋点、1件のみのときは点のみ）
- 一覧は測定日時の新しい順、メモ表示あり
- **プレミアム**: ツールバーの共有アイコンから身体記録を **CSV** エクスポート（`ExportService.buildBodyMeasurementsCSV`、体重列は kg）

### 5.5 履歴/統計/ホーム

- カレンダー:
  - 実施日のコントラストを強化
- ホーム:
  - 今週のセッション数・総挙上・**連続週**（統計の「連続実施」と同じ週数）をカード表示
  - **未完了セッション**: `HomeViewModel` は `fetchIncompleteSession` と `incompleteSessionBannerSubtitle`（今日／昨日／N日前の文言）を**保持するが、ホーム先頭の「続きから」バナー UI は表示しない**（未完了の再開は `WorkoutRepository.resolveDraftForStartingWorkoutToday` 経由の当日ドラフト等で扱う）。
  - **停滞インサイト**: 条件を満たすと `stagnationInsightMessage` をカード表示し、`retention_insight_shown`（kind: `stagnation`）をログ。
  - **復帰メッセージ**: `comebackMessage` は計算・`retention_insight_shown`（kind: `comeback`）ログのみ。**カード UI は表示しない**。
- 種目詳細統計:
  - PR、推定1RM、各種チャート
  - PR定義説明を明示
- 統計（一覧）:
  - **Phase 13**: 非プレミアムはグラフ系を「直近1ヶ月相当」に制限（週次系は5週、月間ボリューム比較は1ヶ月、部位別実施回数は直近1ヶ月のセッションのみ）。プレミアムは従来どおり週次12週・月間6ヶ月・部位は全期間。ワークアウト回数・全期間総挙上・連続週・PR履歴は無料でも従来どおり。一覧先頭に `PremiumCTAView` への導線。
  - **週次総挙上の推移**: `WorkoutStatsService.weeklyTotalVolumes`（プレミアムは直近12週、無料は5週）
  - 月間ボリューム比較・週次ボリューム（部位別）・継続ドットは `chartWeekCount` / `chartMonthCount` に合わせる

## 6. 入力・表示ルール

- 重量:
  - 入力は小数可（例: 60.5）
  - 表示は `AppFormatters.formatWeightNumber` で統一
- CSVエクスポート:
  - **ワークアウト**（設定・プレミアム）: セットごとに出力（種目タイプ・スーパーセットID・秒・距離 等の列あり）、補助列あり（`あり` / 空）
    - **全期間**または**開始日・終了日を指定**（`ExportService.sessionExportRange` → `buildSessionsCSV(from:to:)`。完了セッションかつ `startedAt` が半開区間 `[開始日0時, 終了日翌0時)` に含まれる行）
    - 期間指定時は CSV 先頭に `# 対象期間` 行を付与。ファイル名は `RepLog_export_range_*.csv`
  - **身体記録**（身体記録画面・プレミアム）: 測定日時・体重(kg)・体脂肪率(%)・メモ。先頭行にエクスポート日時

## 7. 保存・遷移フロー（現状）

1. 記録画面で「保存」
2. 確認ダイアログ承認
3. `WorkoutRecordViewModel.saveSession()` 実行
4. 保存成功時に `savedSessionId` を親へ返却
5. 記録画面を閉じる
6. 開始画面から `SessionDetailView(sessionId:)` を表示

## 8. 既知の制約・注意

- `WorkoutSet.isAssisted` はストア互換のため Optional 運用
- iOSシミュレータ向けビルドで watch target 環境差が出る場合あり（iOS本体は別途ビルド確認）
- 設計上「シンプル入力モード」はUIトグルを露出していない（内部キーは存在）
- **VoiceOver**: 統計の数値行・グラフ・PR行、記録のセット完了トグルなどに `accessibilityLabel` / `Value` / `Hint` を付与（継続セクションの週ドットは `chartWeekCount` に合わせた要約読み上げ）
- **プレミアム購入直後のレビュー依頼**: `kintore.requestedReviewAfterPremium` で初回のみ（設定の購入ボタン）

## 9. 今後の分析観点（他AI向け）

- UX改善:
  - 記録速度（タップ数、入力完了率）
  - セットコピー導線の利用率
- 継続率改善:
  - 「前回からN日」表示の効果
  - 週次サマリの再訪問への寄与
- データ品質:
  - 小数重量入力の割合
  - 補助フラグ入力率とPR算出への影響
