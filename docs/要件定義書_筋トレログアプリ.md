# 筋トレログアプリ 完全版 要件定義書

**版**: 1.0  
**対象**: iOSアプリ（Swift / SwiftUI）  
**前提**: 個人開発で着手可能なMVP範囲

---

## 1. プロダクト概要

### 1.1 アプリ名の仮称案

| 案 | 読み・イメージ |
|---|---|
| **RepLog** | リップログ。Rep（回数）＋Log。短く覚えやすい。 |
| **LiftNote** | リフトノート。記録の軽さと成長ノートのイメージ。 |
| **SetGo** | セットゴー。セットを記録してすぐ次へ。速さを連想。 |
| **GainTrack** | ゲイントラック。成長を追う。英語圏でも伝わる。 |
| **Kintore Note** | 筋トレノート。日本語で直感的。 |

**推奨**: 記録の速さと継続を訴求するなら **RepLog** または **SetGo**。国内メインなら **Kintore Note** も候補。

### 1.2 解決したい課題

- **記録のハードルが高い**: 高機能アプリは入力項目が多く、ジムで片手で素早く記録できない。
- **継続できない**: 記録が面倒で挫折する。または単純メモアプリでは前回値が見づらく「次をどうするか」が分からない。
- **成長実感が薄い**: 記録はするが前回比較・PR・推移が一目で分からず、モチベーションに繋がらない。
- **次回への引き継ぎが弱い**: 自由メモだけでは「次は重量を上げるか」「フォームを直すか」が整理されない。

### 1.3 提供価値

- **最短で記録できる**: 起動後すぐ記録、前回コピー・クイック増減でタップ数を最小化。
- **前回より少し良くする**: 前回値・ベスト・PRが常に見え、重量アップ・rep追加の判断がしやすい。
- **続けやすい**: ゲーミフィケーション過多にせず、途切れても再開しやすい静かな継続支援。
- **次回に活きるメモ**: フォーム・疲労・痛みなどをタグで構造化し、次回の改善に繋がる。

### 1.4 既存アプリとの差別化

| 軸 | 海外高機能アプリ | 国内メモ系 | 本アプリ |
|---|---|---|---|
| 入力 | 項目多・設定多 | 自由記述中心 | 前回コピー・クイック増減で最小タップ |
| 前回参照 | ありだが深い | 弱い | 記録画面で常に前回・PR表示 |
| 継続 | バッジ・ストリーク依存 | 特になし | 静かな提案・再開しやすいUI |
| メモ | 自由文のみ | 自由文のみ | タグで構造化、次回参照しやすい |
| 対象 | 上級者・分析志向 | 誰でも | 初心者〜中級者・記録を続けたい層 |

### 1.5 ターゲットユーザー

**主ターゲット**

- 20代〜40代、ジムで筋トレする一般ユーザー。
- 初心者〜中級者。細かい分析より「成長実感が欲しい」層。
- 複雑なアプリを嫌い、記録で挫折した経験がある。
- 片手で素早く記録したい（ジム現場での利用）。

**サブターゲット**

- 自宅トレーニー、簡易記録したい経験者。
- SNSは不要だが進捗は見たい層。

**ターゲット外**

- 競技志向の上級ボディビルダー向け特化。
- 食事・睡眠・サプリ・コミュニティまで一元管理を求める層。

### 1.6 利用シーン

- **ジムでセット間**: セット完了→休憩タイマー開始→次セット前に重量・回数をクイック入力。
- **ジム到着時**: アプリ起動→「前回のルーティンで開始」→種目を順に記録。
- **帰宅後**: 軽くメモタグを追加（フォーム崩れ・疲労など）。
- **週末**: 履歴・カレンダー・統計で週の実施回数・部位バランスを確認。
- **ブランク後**: アプリを開く→「続きから」またはルーティン選択で再開。

## 2. プロダクトコンセプト

### 2.1 一言コンセプト

**「最短で記録できて、前回より少しだけ良くする筋トレログアプリ」**

### 2.2 UXコンセプト

- **速い**: 起動→記録までのステップを最小化。前回コピー・「+1rep」「+2.5kg」で数値入力を減らす。
- **見える**: 前回の重量・回数・セット数・PRが記録画面で常に見える。
- **続く**: 押しつけがましくない進歩提案と、途切れても「続きから」で再開しやすい導線。
- **繋がる**: 構造化メモで「次回何を気をつけるか」が明確になる。

### 2.3 コア体験

1. **記録時**: 種目選択→前回値が表示→「前回と同じ」or 数値だけ変更→セット完了。所要時間を意識しないほど短い。
2. **セット間**: 休憩タイマーが自動 or 手動で動く。戻ったら次のセットを同様に記録。
3. **終了後**: 所要時間・総挙上重量がすぐ分かる。必要ならメモタグを付ける。
4. **後日**: 履歴・カレンダー・種目別推移で「前回より良くしたか」が一目で分かる。

### 2.4 なぜこの体験が刺さるのか

- 既存は「記録のための操作」が多く、本アプリは「記録が邪魔にならない」設計。
- 前回値が常に見えるため、重量アップの判断が迷わない。
- 継続支援が「静か」なので、プレッシャーで離脱しにくい。
- タグメモで「次に活かせる」実感が得られる。

### 2.5 競争優位の仮説

- **入力速度**: 1セットあたりのタップ数・起動から記録までの時間で定量比較可能。ここで上回ればジム利用シーンで選ばれやすい。
- **継続率**: 再開導線・ルーティン再開・過度な通知依存を避ける設計で、長期利用につなげる。
- **見た目と実用**: 洗練されたミニマルUIで信頼感と「使いたい」を両立し、App Storeでの訴求力を高める。

## 3. MVP定義

### 3.1 初版に含める機能一覧

| 大分類 | 機能 |
|---|---|
| 記録 | ワークアウト記録（種目・重量・回数・セット・メモ・開始/終了時刻・所要時間）、セット完了チェック |
| 種目 | 種目マスタ（プリセット・カスタム・部位/器具タグ・検索・お気に入り） |
| 前回参照 | 前回の重量・回数・セット表示、ベスト記録表示、前回値コピー、前回比較表示 |
| ルーティン | テンプレ保存、種目並び替え・追加・削除、部位別テンプレ、PPL等の分割対応構造 |
| 休憩 | 休憩タイマー（セット完了時自動開始、手動開始/停止、種目別デフォルト、通知方針） |
| 履歴 | 日付別・カレンダー・種目別・ルーティン別履歴 |
| 保存 | オフライン・ローカル完結、起動即入力可能 |
| 統計 | ワークアウト回数、総挙上重量、種目別推移、PR更新履歴、部位別頻度 |
| クイック記録 | 起動後すぐ記録、前回ルーティン再開、「前回と同じ」「+1rep」「+2.5kg」、数値入力しやすいUI |
| メモ | 構造化メモ（フォーム崩れ・左右差・疲労・睡眠不足・痛み・混雑・器具待ち・集中・パンプ等タグ） |
| 進歩提案 | 前回達成時の重量アップ候補、未達続き時の維持提案、メモを考慮した無理な提案抑制 |

### 3.2 初版に含めない機能一覧（将来拡張で明記）

SNS/コミュニティ、食事管理、睡眠管理、動画フォーム解析、AIコーチング全面搭載、課金、Apple Watch本格対応、Apple Health深い連携、写真進捗、音声入力、CSV/クラウド同期、共有、通知マーケティング。

### 3.3 なぜこのMVPが妥当か

- **記録・種目・前回参照・ルーティン・休憩**: 差別化の核「最短記録」「前回比較」を成立させる最小セット。
- **履歴・統計**: 成長実感と継続理由を提供。実装はCRUD＋集計で範囲が明確。
- **クイック記録・構造化メモ・進歩提案**: 入力速度と「次回に活きる」を実現する必須要素。
- **オフライン**: ジムの通信環境に依存せず、起動即入力を保証するため必須。

### 3.4 開発優先順位

1. **Phase 1（基盤）**: データモデル、種目マスタ（プリセット＋CRUD）、ワークアウト記録（1種目・複数セット）、ローカル保存。前回記録取得・表示。
2. **Phase 2（記録体験）**: ルーティン（テンプレ保存・並び替え）、クイック記録（前回コピー・+rep・+kg）、休憩タイマー、構造化メモタグ。
3. **Phase 3（振り返り）**: 履歴一覧・カレンダー、種目別/ルーティン別履歴、基本統計（回数・総挙上・PR・部位別）。
4. **Phase 4（仕上げ）**: 進歩提案ロジック、ホーム画面の最適化、デザイン仕上げ・アニメーション、設定（休憩デフォルト等）。

## 6. 主要画面の詳細仕様

### 6.1 ホーム

**目的**: 起動後すぐ「今日の記録」に繋げる。直近の文脈（前回ルーティン・最後の記録日）を見せる。情報は少なめにし、迷わない。

**情報構造（ワイヤー風）**

```
+------------------------------------------+
| [アプリ名]                    [設定アイコン]
+------------------------------------------+
|                                          |
|   [ 今日のワークアウトを記録 ]  (主CTA)   |
|                                          |
|   --- クイックアクション ---              |
|   [ 前回のルーティンで続ける ]            |
|   [ ルーティンを選ぶ ]                   |
|                                          |
|   --- 直近 ---                           |
|   3/8(日) 胸・肩  5種目  約45分           |
|   3/6(金) 脚     4種目  約40分           |
|   [ 履歴をもっと見る ]                    |
|                                          |
|   --- 今週のサマリ（任意） ---            |
|   実施 3回  総挙上 12,500 kg              |
|   [ 統計を見る ]                          |
+------------------------------------------+
| [ホーム] [履歴] [統計] [設定]  (Tab)     |
+------------------------------------------+
```

**主なUI要素**

- メインCTA: 「今日のワークアウトを記録」。タップで「今日のワークアウト開始」へ。
- 前回ルーティンで続ける: 直近で使ったルーティンをそのまま種目リストで開く。2タップで記録開始。
- ルーティンを選ぶ: ルーティン一覧へ。
- 直近2〜3件: 日付・ルーティン名・種目数・所要時間。タップでその日のセッション詳細へ。
- 今週サマリ: 実施回数・総挙上。控えめに表示。統計への導線。

**注意すべきUX**

- ホームに種目一覧や統計を詰め込まない。記録開始と「続きから」を最優先。
- 前回ルーティンは「名前」または「最終実施日」で分かるようにする。

---

### 6.2 ワークアウト記録画面

**目的**: セッション中の全種目・全セットを記録する。前回値が常に見え、クイック入力（前回コピー・+rep・+kg）でタップ数を減らす。片手操作を前提に。

**情報構造（ワイヤー風）**

```
+------------------------------------------+
| [< 戻る]  ワークアウト中     [終了]       |
| 開始 10:24  経過 12分                    |
+------------------------------------------+
| 種目: ベンチプレス          [種目変更]   |
| --- 前回 ---  40kg x 10 x 3  最終 3/6   |
| --- ベスト --- 42.5kg x 8 (3/1)         |
+------------------------------------------+
| セット1  [40] kg  [10] rep  [完了]       |
| セット2  [40] kg  [10] rep  [完了]       |
| セット3  [  ] kg  [  ] rep  [記録]       |
|                                          |
| [前回と同じ] [+1rep] [+2.5kg] [-2.5kg]   |
+------------------------------------------+
| メモ  [フォーム崩れ] [疲労強い] [+タグ]  |
+------------------------------------------+
| [休憩 90秒] 00:45  [スキップ] [延長]     |
+------------------------------------------+
| [次の種目へ]  or  [ワークアウトを終了]   |
+------------------------------------------+
```

**主なUI要素**

- ヘッダ: 戻る、経過時間、終了ボタン。終了で所要時間確定・保存。
- 種目ブロック: 種目名、前回（重量×回数×セット数、日付）、ベスト（重量×回数、日付）。種目変更で種目選択へ。
- セットリスト: 各セットで重量・回数・完了。未記録セットは入力欄＋「前回と同じ」「+1rep」「+2.5kg」等。
- メモ: タグを複数選択。必要なら自由文1行を補足。
- 休憩: セット完了で自動開始（種目別デフォルト）。表示は残り時間。手動スキップ・延長。
- フッタ: 次の種目へ / ワークアウト終了。

**クイック入力の仕様**

- 「前回と同じ」: 前回の重量・回数をそのセットにコピー。1タップ。
- 「+1rep」: 前回回数+1をセット回数にセット。
- 「+2.5kg」「-2.5kg」: 前回重量±2.5kg（単位は設定に従う）。
- 数値はスライダーまたはスッテッパーで変更可能だが、クイックボタンで大半を賄えるようにする。

**遷移**

- 種目変更 → 種目追加/編集（モーダルまたはプッシュ）。選択で戻る。
- 次の種目へ → 同一画面で種目を切り替え（ルーティン順）。新規種目は種目選択から追加。
- ワークアウト終了 → 確認ダイアログ → 保存 → ホームまたは履歴。

**注意すべきUX**

- 前回・ベストは常に同じ位置に表示し、比較しやすくする。
- セット追加は「+セット」で行い、デフォルトは前回セット数に合わせる。
- 休憩中は画面を離れてもタイマーは継続（バックグラウンド方針は「休憩タイマー」で定義）。

---

### 6.3 クイック記録モード

**位置づけ**: ワークアウト記録画面そのものを「クイック記録モード」として設計する。別画面ではなく、以下の挙動で実現する。

- **起動後すぐ**: ホームの「今日のワークアウトを記録」→ ルーティン選択 or 前回で続ける → 即セッション開始。種目入力は「前回ルーティン」なら0タップ。
- **前回と同じ**: 1タップで重量・回数を現セットに反映。
- **+1rep / +2.5kg**: 1タップで前回から一定ルールで増加。
- **数値入力**: 重量・回数はピッカー or ステッパーで変更。デフォルトは前回値。

**追加仕様**

- 種目追加時: 直近使った種目を上位表示。お気に入りも上位。
- ルーティン未使用時: 種目選択後、前回のセット数でセットを自動生成し、あとは数値だけ直す形で済むようにする。

### 6.4 履歴・統計画面

**履歴一覧**

- 日付の降順。各日はカードまたは行で「日付・ルーティン名（任意）・種目数・所要時間・総挙上（任意）」を表示。
- タップでその日のセッション詳細（種目・セット一覧、メモ）。
- 上部にカレンダーへの導線。

**カレンダー**

- 月表示。実施日はマーク（ドットまたは塗り）。タップでその日の履歴へ。
- 週・月の切替は任意（初版は月で十分）。

**種目詳細/推移**

- 種目を指定して表示。期間（1ヶ月/3ヶ月/6ヶ月/全期間）を切替。
- 重量・回数の推移を折れ線またはバーで表示。PRは注釈または別表示。
- 直近セットのリスト（日付・重量×回数×セット数）。

**統計**

- ワークアウト回数（今週/今月/全期間）。
- 総挙上重量（同）。
- 部位別実施回数（円グラフまたはバー）。
- PR更新履歴（種目・内容・日付）のリスト。
- 種目別サマリ（種目名・実施回数・直近重量）→ タップで種目詳細/推移へ。

**UX**

- 数字と前回比較はフォントサイズ・コントラストで視認性を最優先。
- グラフは色数を抑え、凡例を分かりやすく。ダーク/ライト両対応。

## 7. ユーザーフロー

### 7.1 初回利用フロー

1. アプリ起動 → ホーム（または簡易オンボarding「記録を始めよう」1枚）。
2. 「今日のワークアウトを記録」→ ルーティンなしのため「新規で開始」 or 「ルーティンを作成」を案内。
3. 新規で開始 → 種目選択（プリセットから選択）→ 重量・回数・セット入力 → セット完了 → 終了。
4. 次回からは「前回のルーティンで続ける」またはルーティン一覧が使える。

（オンボardingは最小限。種目プリセットは初回から利用可能とする。）

### 7.2 通常の記録フロー

1. 起動 → ホーム。
2. 「前回のルーティンで続ける」タップ → セッション開始、1種目目が表示。
3. 各セット: 前回値表示のまま「前回と同じ」または「+1rep」等で記録 → セット完了 → 休憩タイマー。
4. 次の種目へ → 同様に記録。
5. 終了 → 所要時間・総挙上が表示（任意）→ ホームへ。

### 7.3 ルーティン作成フロー

1. ホーム or 設定から「ルーティン」→ ルーティン一覧。
2. 「新規作成」→ 名前入力（任意）→ 種目を追加（検索・フィルタで選択）、並び替え。
3. 保存 → ルーティン一覧に表示。開始画面から選択可能に。

### 7.4 履歴確認フロー

1. ホーム or Tab「履歴」→ 履歴一覧。
2. 日付タップ → セッション詳細。またはカレンダーで月を見て日付タップ → 同様。
3. 種目名タップ（詳細がある場合）→ 種目詳細/推移。

### 7.5 ブランク後の再開フロー

1. 起動 → ホーム。直近履歴に「最終 3/1」等が表示されている。
2. 「前回のルーティンで続ける」で同じルーティンで開始。または「ルーティンを選ぶ」で任意のテンプレを選択。
3. 記録画面では前回値がそのまま表示されるため、続きから入力できる。特別な「再開」専用UIは必須ではないが、ホームで「続きから」を分かりやすくする。

### 8.1 エンティティ定義

| 用途 | 種目マスタ。プリセットとユーザー追加を同一モデルで扱う。 |

| 型イメージ | id: UUID, name: String, memo: String?, sortOrder: Int, createdAt: Date, lastUsedAt: Date? |
| リレーション | WorkoutTemplateItem を 1:N で持つ。WorkoutSession が templateId を optional で持つ。 |

| 項目 | 内容 |
|---|---|
| 用途 | テンプレに含まれる種目と順序。 |
| 主なカラム | id, workoutTemplateId, exerciseId, order |
| 型イメージ | id: UUID, workoutTemplateId: UUID, exerciseId: UUID, order: Int |
| リレーション | WorkoutTemplate に属する。Exercise を参照。 |
| 保持理由 | 並び替え・テンプレ適用時に種目リストを再現。 |

#### WorkoutSession（セッション）

| 項目 | 内容 |
|---|---|
| 用途 | 1回のワークアウト単位。開始/終了時刻・所要時間・テンプレ参照。 |
| 主なカラム | id, startedAt, endedAt, durationSeconds, workoutTemplateId, createdAt |

| 保持理由 | 履歴の日付・所要時間・ルーティン別集計の単位。 |

#### WorkoutExercise（セッション内種目）

| 項目 | 内容 |
|---|---|
| 用途 | 1セッション内の1種目。順序とメモタグ。 |
| 主なカラム | id, workoutSessionId, exerciseId, order, memoTagIds, freeMemo, createdAt |
| 型イメージ | id: UUID, workoutSessionId: UUID, exerciseId: UUID, order: Int, memoTagIds: [UUID] or 文字列配列, freeMemo: String?, createdAt: Date |

| 項目 | 内容 |
|---|---|
| 用途 | 1種目内の1セット。重量・回数・完了有無。 |
| 主なカラム | id, workoutExerciseId, weight, reps, order, completedAt |
| 型イメージ | id: UUID, workoutExerciseId: UUID, weight: Decimal?, reps: Int?, order: Int, completedAt: Date? |
| リレーション | WorkoutExercise に属する。 |
| 保持理由 | 前回値・PR・総挙上・推移の元データ。 |

#### MemoTag（メモタグマスタ）

| 項目 | 内容 |
|---|---|
| 用途 | 構造化メモのタグ定義。固定＋将来のユーザー追加を考慮。 |

| 型イメージ | id: UUID or 固定ID, label: String, category: String?, sortOrder: Int |

| 項目 | 内容 |
|---|---|
| 用途 | 種目ごとのベスト記録。重量×回数 or 重量のみ等、ルールを決めて保持。 |

| 型イメージ | id: UUID, exerciseId: UUID, weight: Decimal, reps: Int?, achievedAt: Date, recordType: String |
| リレーション | Exercise を参照。 |
| 保持理由 | 記録画面の「ベスト」表示、統計のPR履歴。計算で都度求めるか、更新時に書き込むかは実装で選択。 |

#### UserPreference（ユーザー設定）

| 項目 | 内容 |
|---|---|
| 用途 | 休憩デフォルト、単位（kg/lb）、テーマ（ダーク/ライト/システム）、種目別休憩の上書き等。 |
| 主なカラム | defaultRestSeconds, weightUnit, theme, perExerciseRestOverrides(json or 別テーブル), createdAt, updatedAt |
| 型イメージ | シングルトンまたは key-value。defaultRestSeconds: Int, weightUnit: String, theme: String |
| リレーション | なし。 |
| 保持理由 | 休憩タイマー・表示単位・見た目の統一。 |

### 8.2 前回記録取得ロジック

- **前回**: 同一 exerciseId について、endedAt が存在する WorkoutSession に紐づく WorkoutExercise のうち、最も endedAt（または startedAt）が新しい1件。その WorkoutSet を重量・回数・セット数として表示。
- **複数種目**: セッション単位で「前回のセッション」を取る場合は、同一 templateId または「直近1セッション」でセッションを特定し、その中の種目順・各種目のセットを前回として表示。

### 8.3 PR判定の考え方

- **重量×回数**: 1セットの weight × reps を「 volume 」とし、同一種目で最大の volume をPRとする。または「最大重量（同一回数以上）」をPRとする等、ルールを1つに固定。
- **更新タイミング**: セット保存時（またはセッション終了時）に、その種目の既存PRと比較し、上回れば PersonalRecord を insert/update。achievedAt はそのセットの completedAt。
- **表示**: 記録画面では「ベスト 42.5kg x 8 (3/1)」のように、重量・回数・日付を表示。

### 8.4 総挙上重量の計算式

- **1セット**: weight × reps。重量未入力・回数未入力のセットは 0 として扱う。
- **1種目**: その種目の全セットの合計。
- **1セッション**: セッション内全種目・全セットの weight × reps の合計。
- **期間**: 対象期間の全セッションの総挙上を合計。

### 8.5 構造化メモの保持方法

- WorkoutExercise に memoTagIds: [UUID] を持たせる。または tag を文字列で持たせ、MemoTag マスタと照合して表示。
- タグは初版は固定リスト（フォーム崩れ・左右差・疲労強い・睡眠不足・痛みあり・混雑・器具待ち・集中できた・パンプ強い等）。ID または文字列で保持し、WorkoutExercise に複数選択可能で保存。
- 自由文は freeMemo: String? で1行程度を想定。長文は将来拡張とする。

## 10. デザイン要件

### 10.1 デザインコンセプト

**「洗練されたミニマルUI × 少しだけ高揚感のあるフィットネス感」**

- 男性・女性の両方に受け、ガチすぎず軽すぎない。
- 継続利用しても疲れない。情報整理は明確で実用性を優先。
- スクショ映えし、「今っぽい人気アプリ」に見えるが、派手ではない。

### 10.2 UI原則

- iOSネイティブをベースに、ややモダンに寄せる。過剰な装飾はしない。
- 角丸・余白・階層・タイポグラフィで上品さを出す。
- 片手操作しやすい下部導線。数値入力・記録・完了を最優先。
- ホームは情報過多にしない。「前回との比較」が一目で分かるUIを記録画面で実現。

### 10.3 カラー方針

- **ベース**: ダーク寄りを初版のデフォルトとし、ライトモードも完全対応。黒・チャコール・オフホワイトを軸。
- **背景**: ダーク時は #0D0D0D〜#1A1A1A、ライト時は #F5F5F5〜#FFFFFF。カードは一段明るく/暗くして階層を表現。
- **アクセント**: 1色に絞る。例: ライムグリーン #B8E986、またはブルー #5AC8FA、オレンジ #FF9500。CTA・完了・PR表示に使用。エネルギー感を出すが、面積は抑える。
- **テキスト**: プライマリは高コントラスト（白/黒）、セカンダリは不透明度で弱める。
- **数値・前回比較**: アクセントまたは強調色で視認性を最優先。

### 10.4 タイポグラフィ方針

- 見出し: SF Pro Display または Rounded（Bold/Semibold）。サイズは階層で 22pt / 17pt / 15pt 程度。
- 本文・数値: SF Pro Text。重量・回数は Semibold で大きく（例: 20pt）。
- 前回・ベストのラベル: Caption または Footnote、色はセカンダリ。
- 行間・字間はデフォルトでよく、長文は行間をやや広く。

### 10.5 ボタン・カード・入力欄・グラフ

- **ボタン**: 主CTAは角丸（12pt程度）、アクセント背景。セカンダリはアウトラインまたはグレー背景。タップ領域は 44pt 以上。
- **カード**: 角丸 16pt、影は控えめ。余白を十分取り、詰めない。
- **入力欄**: 枠線または背景でブロック化。フォーカス時はアクセントの枠。数値はステッパーまたはピッカーで誤操作を減らす。
- **グラフ**: 折れ線またはバーはアクセント1色＋グレー。凡例は短く。シンプルで見栄え良く。

### 10.6 ダークモード・ライトモード

- システム設定に従う「システムに合わせる」をデフォルトとし、設定で「常にダーク」「常にライト」を選べるようにする。
- 両モードでコントラスト比（WCAG 2.1 AA 相当）を満たす。グラフ・アイコンも両モードで見やすい色に。

### 10.7 競合より魅力的に見せる要点

- 余白を広くし、1画面の情報量を抑える。
- 数字と前回比較を大きく・はっきり表示する。
- アイコンは単色・細線・統一感。フィットネス感は色とフォントで出す。
- 「スマートな成長管理」を感じさせるトーンにし、泥臭さは出しすぎない。

### 10.8 App Storeスクリーンショット映えの観点

- 記録画面: 前回値・ベスト・クイックボタンが整理されて写る構図。
- 統計/グラフ: シンプルで色が揃った推移グラフを1枚入れる。
- カレンダー: 実施日が分かる月表示を1枚。
- キャプションは「最短で記録」「前回より少し良く」を短く伝える。

### 10.9 継続利用時に疲れない理由

- 配色を抑え、アクセントを1色に絞る。
- アニメーションは軽く（0.2〜0.3秒）、派手な動きを避ける。
- ホームと記録画面の構成を変えすぎず、慣れで操作できるようにする。

## 11. 実装方針

### 11.1 推奨アーキテクチャ

- **MVVM** を基本。View は SwiftUI、ViewModel は ObservableObject（または @Observable）で State を保持し、モデル・ユースケースを呼び出す。
- **単一責任**: 画面ごとに ViewModel を分ける。共通ロジック（前回取得、PR判定、総挙上計算）は Service または UseCase に集約。
- **永続化**: リポジトリ層を用意し、ViewModel はリポジトリのインターフェースに依存。中で Realm / SwiftData / Core Data のいずれかを利用。

### 11.2 状態管理方針

- 画面単位の状態は ViewModel の @Published（または @Observable のプロパティ）で保持。
- ルーティン選択・種目選択などはモーダルまたは子画面に閉じ、結果をコールバックまたは Binding で親に返す。
- アプリ全体で共有する設定（UserPreference）は Environment または Singleton の設定サービスで注入。

### 11.3 保存方式候補比較

| 方式 | メリット | デメリット | 推奨 |
|---|---|---|---|
| **SwiftData** | SwiftUI と相性が良い、宣言的、iOS 17+ | まだ歴史が浅い、マイグレーションの事例が少ない | ○ 新規開発で iOS 17 以上を取るなら |
| **Realm** | 高速、スキーマ変更が比較的容易、クロスプラットフォーム | 依存が増える、バイナリサイズ | ○ 実績を重視する場合 |
| **Core Data** | ネイティブ、Apple サポート、既存知見が多い | ボイラープレートが多く、SwiftUI とは別途ラップが必要 | △ 既存資産がある場合 |

**初版推奨**: **SwiftData**（ターゲット iOS 17+ でよい場合）。または **Realm**（iOS 16 以下もサポートする場合）。個人開発では SwiftData でシンプルに始め、モデルを ID ベースにしておけば将来の同期拡張にも対応しやすい。

### 11.5 モデル / ViewModel / View 分割方針

- **Model**: エンティティ（Exercise, WorkoutSession 等）は SwiftData または Realm のモデルとして定義。ドメイン用の軽量 DTO を別に持つかは任意。
- **ViewModel**: 画面ごとに1つ。リポジトリと Service を注入し、@Published で View にバインドする状態を用意。入力イベントはメソッドで受け、リポジトリ/サービスを呼ぶ。
- **View**: SwiftUI のみ。ロジックは書かず、ViewModel の状態とメソッドを参照。共通パーツは Components に切り出す。

### 11.6 ユーティリティ責務

- 日付の「今日」「今週」「今月」範囲、表示用フォーマット（日付・時間・重量・回数）。
- 単位変換（kg ↔ lb）は設定に従い Service または UserPreference で一元化。
- 前回取得・PR判定・総挙上計算は **Service** に集約し、Repository は CRUD のみに近づける。

### 11.7 テスト観点

- **ユニット**: 前回取得ロジック、PR判定、総挙上計算、進歩提案（重量アップ/維持）のロジック。ViewModel はリポジトリをモックして入力→出力を検証。
- **UI**: 重要画面（記録画面・ホーム）のスナップショットテストは任意。手動で「前回コピー」「+1rep」の動作確認を優先。

### 11.8 初版で実装難易度が高い箇所

- **休憩タイマーとバックグラウンド**: アプリがバックグラウンドでも残り時間を正確にし、通知で戻す設計。タイマーは Date の目標時刻で持つとよい。
- **前回ルーティン再開**: テンプレと直近セッションの対応づけ、種目順の一致。テンプレ編集で種目が変わった場合は「可能な範囲で」前回値をマッピングするルールを決める。
- **進歩提案**: メモタグ（痛みあり等）を見て提案を出さない条件の整理。閾値（何回未達で維持提案にするか）のチューニング。

## 13. リスクと対策

| リスク | 内容 | 対策 |
|---|---|---|
| 既存アプリとの差別化不足 | 入力速度・継続で差がつかない | タップ数・起動〜記録時間を自分で計測し、クイック記録・前回コピーを徹底。ユーザーテストで「速い」と感じるか検証。 |
| 機能過多 | MVP に欲張ってスコープが膨らむ | 本要件の Phase 1〜4 の順を守り、Phase 4 までで「出せる」ラインを切る。進歩提案はシンプル版のみ。 |
| 継続率低下 | 記録しても続かない | 静かな継続支援に留め、再開導線（前回ルーティン・直近履歴）を目立たせる。通知は休憩のみ。 |
| UI 複雑化 | 画面がごちゃつく | ホーム・記録画面の情報量を厳守。設定は「休憩・単位・テーマ」程度に限定。 |
| ローカル保存の限界 | 端末紛失・機種変更でデータ消失 | 初版では注意喚起。将来のエクスポート・クラウド同期で解消。 |
| 個人開発の実装負荷 | 一人で全機能は負荷が大きい | Phase 1 で「記録と前回表示」までをまずリリース可能にする。休憩タイマー・進歩提案は Phase 2 以降で追加。 |

## 14. 最終提案

### 14.1 勝ち筋

- **記録の速さ**でジム利用シーンで「これが一番ラク」と言われること。
- **前回比較が常に見える**ことで、重量アップの判断が迷わず、成長実感が得られること。
- **見た目**で「信頼できる・飽きない」と感じてもらい、App Store でスクショが伝わりやすいこと。

### 14.2 MVP でまず作るべきもの

1. 種目マスタ（プリセット＋カスタム）とローカル保存。
2. ワークアウト記録（1セッション・複数種目・複数セット）、開始/終了時刻・所要時間。
3. 前回の重量・回数・セット数の表示と「前回と同じ」コピー。
4. ルーティン（テンプレ保存と適用）。
5. クイック入力（+1rep、+2.5kg）。
6. 休憩タイマー（種目別デフォルト、手動開始/停止）。
7. 履歴（日付別・カレンダー）と基本統計（回数・総挙上・PR・部位別）。
8. 構造化メモ（タグ）と軽い進歩提案。
9. ホームは「今日の記録」「前回ルーティンで続ける」を最前面にした構成。

### 14.3 App Store で刺さる訴求文の方向性

- 「最短で記録。前回より、少しだけ良く。」
- 「前回の重量・回数がすぐ見える。迷わず、次を記録。」
- 「ジムで片手でサクッと。続けやすい筋トレログ。」

### 14.4 開発開始時の実装順序

1. プロジェクト作成、SwiftData または Realm の導入、エンティティ定義（Exercise, WorkoutSession, WorkoutExercise, WorkoutSet, WorkoutTemplate, WorkoutTemplateItem, MemoTag, UserPreference）。
2. 種目マスタの CRUD とプリセット投入、種目ピッカー画面。
3. ワークアウト記録画面（1種目・複数セット）、保存と前回取得ロジック。
4. ルーティン（テンプレ保存・編集・適用）。「前回ルーティンで続ける」。
5. クイック入力（前回コピー・+rep・+kg）、休憩タイマー、構造化メモタグ。
6. 履歴一覧・カレンダー・セッション詳細、種目詳細/推移。
7. 基本統計、PR 判定・総挙上計算、進歩提案の簡易ロジック。
8. ホームの最適化、設定画面、デザイン・カラー・タイポの統一、軽いアニメーション。
9. テストと調整、App Store 用スクリーンショット・説明文の準備。

以上で、実務でそのまま開発に着手できる粒度の要件定義書とする。
